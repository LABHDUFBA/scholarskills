Como utilizar uma skill

Do clone à verificação de que o agente reconheceu a skill, sem confundir instalação com ativação.

Antes de começar

Uma skill não é um programa que se instala e roda sozinho. Ela é um conjunto de instruções e, às vezes, de scripts que um agente lê para conduzir uma tarefa. Instalar uma skill significa colocá-la onde o agente procura por skills; usá-la significa pedir ao agente que a consulte e conferir o que ele fez.

Você precisa de três coisas: Python 3.10 ou superior para os pacotes que trazem scripts, Git para obter o repositório e um agente compatível com Agent Skills. Algumas skills pedem rede ou credenciais próprias; a página de cada pacote lista o que é obrigatório e o que é condicional.

1. Escolha o ambiente

Hermes Agent. Skills ficam em $HERMES_HOME/skills/, por padrão ~/.hermes/skills/. Depois de copiar um pacote, comece uma sessão nova e confira com hermes skills list; dentro da sessão, /skills lista e /skill <nome> carrega uma skill.

Claude Code. Skills pessoais ficam em ~/.claude/skills/<nome>/SKILL.md e valem em todos os projetos; skills de projeto ficam em .claude/skills/ na raiz do repositório. O nome do diretório se torna o comando /nome.

Outro ambiente compatível. Siga a especificação Agent Skills do próprio ambiente. Não presuma que o caminho de um agente vale para outro.

2. Obtenha o pacote

O repositório reúne todas as skills. Para uma skill isolada, copie apenas o diretório dela.

git clone https://github.com/LABHDUFBA/scholarskills.git
cd scholarskills

3. Ative a skill no agente

Hermes Agent:

mkdir -p ~/.hermes/skills
cp -R zotero-reference-management ~/.hermes/skills/

Claude Code (pessoal):

mkdir -p ~/.claude/skills
cp -R zotero-reference-management ~/.claude/skills/

4. Verifique se a skill foi reconhecida

Copiar arquivos não prova ativação. No Hermes, hermes skills list deve mostrar o nome da skill; em uma sessão nova, peça: “Liste as skills disponíveis e diga quando você usaria a skill zotero-reference-management.” No Claude Code, o nome do diretório aparece como /zotero-reference-management.

Se a skill não aparecer, confira três coisas: o arquivo SKILL.md está na raiz do diretório copiado; o frontmatter tem name e description válidos; a sessão foi iniciada depois da cópia.

5. Configure requisitos com cuidado

Leia a seção Requisitos da skill. Separe o que é obrigatório do que é condicional, e não instale dependências globais: use um ambiente virtual.

cd zotero-reference-management
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt

Credenciais vão em variáveis de ambiente ou em um arquivo .env que nunca é versionado. Não cole chaves em prompts, exemplos, capturas de tela ou arquivos do repositório. Conceda à chave o menor escopo que resolve a tarefa.

6. Execute um exemplo seguro

Comece pelo exemplo que o pacote documenta, de preferência um que rode com dados sintéticos ou fixtures e sem rede. Peça ao agente que mostre o comando antes de executar e que registre a saída. Operações de escrita em serviços reais exigem confirmação explícita.

7. Leia a evidência antes de confiar

Testes verdes provam que o código faz o que o teste descreve, não que o método é adequado à sua pesquisa. A página Evidências e maturidade explica as dimensões e mostra o que cada pacote registra. O tests/RESULTS.md do pacote traz ambiente, comando e resultado.

8. Cite a versão que usou

Quando existe DOI de versão, cite esse DOI para a execução específica e explique o DOI de conceito como o registro que reúne as versões. A ficha de cada skill traz a citação pronta e os dois identificadores, quando existem.

O que esta revisão testou

Esta revisão verificou o build estático, os links internos e a validação estrutural dos pacotes. Não testou a ativação em Hermes Agent ou Claude Code, chamadas reais às APIs externas, todos os sistemas operacionais nem a adequação científica de cada método. O relatório da revisão registra o que passou, o que falhou e o que não foi executado.
