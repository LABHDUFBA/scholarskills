How to use a skill

From clone to checking that the agent recognised the skill, without confusing installation with activation.

Before you start

A skill is not a program that installs and runs by itself. It is a set of instructions, sometimes with scripts, that an agent reads to carry out a task. Installing a skill means placing it where the agent looks for skills; using it means asking the agent to consult it and checking what the agent did.

You need three things: Python 3.10 or newer for packages with scripts, Git to obtain the repository and an Agent Skills-compatible agent. Some skills need network access or their own credentials; each package page lists what is required and what is conditional.

1. Choose the environment

Hermes Agent. Skills live in $HERMES_HOME/skills/, by default ~/.hermes/skills/. After copying a package, start a new session and check with hermes skills list; inside a session, /skills lists them and /skill <name> loads one.

Claude Code. Personal skills live in ~/.claude/skills/<name>/SKILL.md and apply to every project; project skills live in .claude/skills/ at the repository root. The directory name becomes the /name command.

Other compatible environments. Follow that environment's own implementation of the Agent Skills specification. Do not assume one agent's path applies to another.

2. Get the package

The repository holds every skill. For a single skill, copy only its directory.

git clone https://github.com/LABHDUFBA/scholarskills.git
cd scholarskills

3. Enable the skill in the agent

Hermes Agent:

mkdir -p ~/.hermes/skills
cp -R zotero-reference-management ~/.hermes/skills/

Claude Code (personal):

mkdir -p ~/.claude/skills
cp -R zotero-reference-management ~/.claude/skills/

4. Check that the skill was recognised

Copying files does not prove activation. In Hermes, hermes skills list should show the skill name; in a new session, ask: “List the available skills and say when you would use zotero-reference-management.” In Claude Code, the directory name appears as /zotero-reference-management.

If the skill does not appear, check three things: SKILL.md sits at the root of the copied directory; the frontmatter has valid name and description; the session started after the copy.

5. Configure requirements carefully

Read the skill's Requirements section. Separate what is required from what is conditional, and do not install dependencies globally: use a virtual environment.

cd zotero-reference-management
python3 -m venv .venv
. .venv/bin/activate
python3 -m pip install -r requirements.txt

Credentials belong in environment variables or in a .env file that is never committed. Do not paste keys into prompts, examples, screenshots or repository files. Grant the key the smallest scope that solves the task.

6. Run a safe example

Start with the example the package documents, preferably one that runs on synthetic data or fixtures without network access. Ask the agent to show the command before running it and to record the output. Write operations against real services require explicit confirmation.

7. Read the evidence before trusting it

Green tests prove that the code does what the test describes, not that the method suits your research. The Evidence and maturity page explains the dimensions and shows what each package records. The package's tests/RESULTS.md carries the environment, command and result.

8. Cite the version you used

Where a version DOI exists, cite that DOI for the specific run and explain the concept DOI as the record that gathers the versions. Each skill page provides the ready citation and both identifiers where they exist.

What this revision tested

This revision checked the static build, internal links and structural validation of the packages. It did not test activation in Hermes Agent or Claude Code, real calls to external APIs, every operating system or the scientific adequacy of each method. The revision report records what passed, what failed and what was not run.
