Research Repository Setup

Plan or review a research repository by checking project scope, materials, provenance, data-handling boundaries, and version-control state without imposing a universal directory structure.

What it solves

Help researchers and agents establish or review a project-specific repository, with documentation and provenance that make work navigable and traceable while keeping sensitive material and irreversible actions under human control.

How it works

  1. Inspect the brief, existing files, Git state, branch, remotes, and source-of-truth documents before editing.
  2. Define the project boundary, objective, outputs, non-goals, collaborators, constraints, and completion criteria.
  3. Classify sensitive, restricted, third-party, generated, and bulky materials before moving or staging anything.
  4. Choose a project-specific structure and create only the documentation the work needs.
  5. Record provenance, units, snapshots, filters, transformations, and environment for data-dependent outputs.
  6. Check the final diff and tests; never migrate, commit, push, or publish without explicit authorization.

Limits

There is no universally correct repository tree: the structure must answer to the project's methods, materials, people, governance and outputs. Documentation and version control improve traceability but do not establish scientific validity, reproducibility, legal compliance or secure storage. The script creates a blank starter layout only and cannot infer a research design, institutional policy or rights.
