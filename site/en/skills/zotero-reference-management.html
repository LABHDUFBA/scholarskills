Zotero Reference Management for Research Pipelines

Read, search, export and create Zotero references through the Web API v3, under the principle that the API key defines the boundary of access.

SS-0001 Tested Available Foundation v1.0.0· MIT (code) / CC-BY-4.0 (docs)

Requirements

What you must have before running this skill. Everything required appears here — credentials included.

Zotero API key

RequiredcredentialZOTERO_API_KEY

What it is: A personal key created in your Zotero account. It authorises the skill to read (and, if you allow it, write to) your library.

How to get it: Zotero → Settings → Security → Applications → Create new private key. Grant only the permissions you intend: library read access, write access if the skill will create items, and private library access if that is your case. Copy the key when it is created — it is never shown again.

export ZOTERO_API_KEY="sua_chave_aqui"
Create a key at Zotero ↗Web API v3 documentation ↗

Careful: The key is a credential: keep it out of code, repositories, versioned notebooks and screenshots. Use an environment variable.

Library ID

RequiredidentifierZOTERO_LIBRARY_ID

What it is: Your library number (userID). It appears on the same keys page, next to your username.

How to get it: On the keys settings page, the number next to your username is the library ID. For group libraries, use the group ID.

export ZOTERO_LIBRARY_ID="123456"
See your ID ↗

Careful: It is not secret, but it identifies your account: avoid publishing it alongside research data.

Library type

RequiredsettingZOTERO_LIBRARY_TYPE

What it is: Whether the library is personal (user) or a group library (group).

How to get it: Personal library → user. A shared group library → group (and the ID becomes the group's).

export ZOTERO_LIBRARY_TYPE="user"   # ou "group"

Careful: Not a credential; it determines which endpoint the client queries.

Objective

Turn a Zotero library into a reliable, citable data source for research pipelines: enumerate, filter, export and write references through the Web API v3 — no browser, no scraping, no personal identifiers in the package.

Features

Web API v3Exports BibTeX/CSLRespects the key's scope

How it works

  1. Resolve the library with GET /keys/{key}: the numeric userID and the permission scope.
  2. Count with the Total-Results header and itemType=-attachment, never with the length of a page.
  3. Paginate with start until an empty page — not for a fixed number of iterations.
  4. Export to BibTeX, RIS or CSL JSON; per collection for large libraries, because BibTeX export ignores limit.
  5. Write with POST of a JSON array, and only when the key's scope allows it.
  6. Refuse politely: a 403 is reported as a scope limit, never worked around.
